# CSE-307 Track 1 - Learned Page Replacement

This repository implements **Track 1: Learned Page Replacement (Memory Management)** from the CSE-307 Operating Systems term-paper brief.

The project compares:

- FIFO
- LRU
- Optimal (Belady's)
- A lightweight learned eviction policy using a Decision Tree classifier

The evaluation uses the **same synthetic page-access trace for every policy**. The trace has a deliberate workload shift: the first 300 references are locality-heavy/sequential, while the second 300 references are broader random/bursty accesses.

## 1. What the project demonstrates

The classical policies provide three baselines. The learned policy is trained only on the **before-shift** phase using candidate features that are available from the past:

| Feature | Meaning |
|---|---|
| `recency_distance` | Number of accesses since the candidate page was last referenced |
| `frequency` | Number of references to the candidate so far |
| `recency_rank` | Candidate's rank among resident pages by recency (1 = most recent) |
| `frequency_rank` | Candidate's rank by observed frequency (1 = most frequent) |

For each training eviction decision, the label is generated by Belady's algorithm: `1` means the candidate is the page that should be evicted from the current resident set, otherwise `0`.

**Important:** future references are used only for generating training labels and for evaluating victim-choice agreement. Future information is never used as a runtime feature when the learned policy makes an eviction decision.

The learned model is intentionally frozen after the before-shift training period. This makes the workload-shift experiment easy to explain: it tests whether a simple learned heuristic trained on one access distribution remains reliable after that distribution changes.

## 10. How to explain the algorithms in the demo

**FIFO:** evict the page that entered memory earliest.

**LRU:** evict the page that has not been used for the longest time.

**Optimal:** evict the resident page whose next use is farthest in the future. This requires future knowledge, so it is used here as a benchmark rather than as a realistic online policy.

**Learned:** on a miss, calculate past-only features for every resident candidate, ask the decision tree which candidates look most like historically optimal victims, and evict the candidate with the highest predicted eviction probability.

## 11. Experimental design

I use a controlled workload design consisting of a locality-heavy/sequential first phase followed by a broader random/bursty phase, with identical traces supplied to all policies. **I independently review, finalize, and justify the workload parameters and shift scenario before the final experiment.**

Every policy receives the exact same final trace for a given run. The only thing that changes is the replacement decision made when a page fault occurs. This makes my before/after comparison a controlled experiment rather than a comparison across different workloads.

## 12. Limitations

This is a simulator, not a modification of the Linux kernel. Belady's policy is computationally expensive because it scans future references, but that is acceptable for this small educational experiment. The learned model uses only a few manually selected features and is intentionally shallow, so the experiment studies the effect of a lightweight heuristic rather than optimizing predictive accuracy.

## 13. Analysis and discussion

I analyze the experiment by separating the stable pre-shift phase from the distribution-shifted post-shift phase. The first phase has strong locality, so pages that were recently or frequently referenced are more likely to remain useful. This gives LRU and recency/frequency-based learned features useful information.

The workload then expands to a broader random/bursty access pattern. This reduces the predictive value of historical recency and frequency because a page that was useful recently may not be referenced again soon. The learned model is frozen after training on the first phase, so it cannot immediately update its decision rules when the access distribution changes.

The development/reference run illustrates this effect: the learned policy starts strongly before the shift but suffers the largest hit-ratio drop after the shift. The analysis for the final submission should follow the same logic but must be based on my own measurements. If the final measurements produce a different ranking, I will report and explain that observed result rather than forcing the result to match the reference run.

The page-fault count should be interpreted together with hit ratio. Because the trace length is fixed, a lower hit ratio means more misses and therefore more page faults. Optimal is included as an offline benchmark because it can inspect future references; it is not a realistic online policy. The learned-victim agreement score is useful as a diagnostic, but exact agreement with Optimal does not automatically guarantee the best long-term hit rate because an eviction decision changes the future resident set.

The central research conclusion is therefore about **workload distribution shift**: a learned heuristic can exploit stable locality but may become less reliable when the workload changes. The final conclusion in the submitted report will be based only on the final student-run measurements.
